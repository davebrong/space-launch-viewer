Historical detail amendment: each past record links to a local `/launches/[id]?past=1` page with a new ZIP-specific planning scenario, shared planning assumptions, directions, supported watch intervals, local sunlight, and prelaunch-only cloud data. Do not apply the future 30-day filter or insert archive records into the upcoming catalog. Unknown legacy time precision may support untimed nearby potential from the recorded day, never a fabricated clock. Distinguish potential visibility, outside modeled coverage, unknown, and flight failure; none establishes a sighting or a saved prelaunch forecast.

Viewable now means today through 30 calendar days ahead at the observer location. Remove Upcoming; retain All. Nearby estimates use pad-relative direction and practical watch guidance for every mission family within documented model coverage. Date-only nearby opportunities show time TBA without a sky path or made-up clock time.
Historical browsing amendment: retain location-based Viewable as default, All as the upcoming catalog, and add Past launches for the separate Cape/Kennedy previous-launch archive. Past launches is independent of ZIP eligibility and the 30-day horizon, sorted newest first, with explicit provider total, page retrieval time, original outcome, record-update time and API links. Load older pages on demand through the shared worker/cache and provider budget; never label a partial page as the complete archive.

The latest simplification defaults `/launches` to Viewable for the confirmed location. All exposes the full schedule with unavailable cards marked “No viewing estimate” (or a specific reason). Loading and failure do not temporarily show unclassified launches in Viewable; changing location clears eligibility until recomputed. Keep today's completed plans. Main navigation contains Launches, Reminders and History; hide Observations/Privacy entry points, including detail/footer links, while preserving direct routes.
Issue #1 amendment (2026-10-14, supersedes the simulation wording below): distant planning requires a mission-specific published heading. Lead with “Look [observer directions] in clear skies”, a local watch interval (or “minutes after liftoff” when the time is unconfirmed), and a “Clear-sky estimate” label. Name the departure heading separately as “from the pad” with its source and retrieval time. Never present the departure heading as the observer's viewing direction. Every launch detail has a Mission route information panel. It shows evidence type (published departure heading, hazard area — not a flight path, published path), source link, retrieval time, hash, per-source check states and source changes. List cards keep missing coverage distinct (Route check pending, No published route found, Route not published yet (undated or more than 7 days out, when sources are not expected to have published), Route source unavailable, Route source ambiguous, Hazard areas only; path unresolved, Route sources disagree, Grazes/Below your horizon (modeled)). The launch list leads its route-coverage summary with launches due within 7 days or already flown, then shows all-mission denominators by state and vehicle family. Cloud cover is a secondary note.
The 2026-10-13 practical-planning amendment takes precedence for the optional `planning_scenario`: lead with “Look [direction]” and a broad local watch interval, one “Simulated estimate” label, and collapsed simulation/source details. Completed launches retain this schedule-based scenario. Prelaunch cloud summaries exclude later forecasts. Admitted-evidence states below remain applicable to the separate verified forecast.
Responsive 360px mobile through desktop; keyboard-first semantic HTML, WCAG2.2 AA contrast/focus/labels, reduced motion and screen-reader alternatives. No result conveyed by color alone. SVG is a static approximate band with accessible title and time/direction/elevation table. All source links identify evidence type and age.

## State matrix
Loading: named skeleton/status, aria-busy, retain prior result clearly marked while refresh. Empty: no supported scheduled missions/date results; retain location. Unavailable: specific missing route/profile/weather/time source, show independent facts. Stale: age and last success, no new positives; preserve last archived calculation labeled stale. Error: retryable server error with request ID, no erased location. Unsupported: explicit source format/dogleg/ZIP/date/mission state and no fabricated geometry. Offline: cached history marked offline, mutation action disabled with explanation. Quota: 100-location cap explanatory, existing subscriptions usable. Awaiting confirmation at T0; hold/scrub/cancel/completed distinct with no active countdown. Terminal states do not show as “Unlikely” sightings.

Never infer user point from phone zone; fixed observer point controls all date labels. DST repeated time must display EDT/EST and numeric offset. User changes point -> clear confirmed flag and old assessment until reconfirmed. GPS failure offers manual, never silently uses pad. Subscription setup previews dawn notice suppression before saving. Changed schedule shows revision and recomputed sunlight/weather, not a shifted old plot. Official guidance uses source timing/region only, no invented track curve. Route missing weather may still render separately with label “Weather alone cannot establish launch visibility.”
