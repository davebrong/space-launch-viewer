# Contract semantics
JSON Schema Draft 2020-12, OpenAPI 3.1.0. `.schema.json` models are internal normalized values; external/ contains permissive provider subsets. Raw bytes remain immutable outside normalized tables. Every property in normalized objects is required unless request DTO explicitly says otherwise; nullable means JSON null, never empty string/zero sentinel. Unknown fields reject internally; external adapters tolerate additions but validate used fields. Finite numbers only. Hash SHA-256 lowercase; revisions positive integers; UTC RFC3339 terminal Z required. Schema format checking is enabled by the harness.

Cross-field semantic validations (application must enforce; schema cannot express all):
- Every interval is half-open [start,end), end>start; source instantaneous events are separate timestamps. Launch window includes both possible launch-time endpoints for alternatives. Emission intervals exclude cutoff; a left-limit at cutoff can establish elapsed duration but is not another powered sample.
- ZIP preserved string; GPS/manual lat/lon pair either both present or absent. Location input must specify ZIP XOR coordinates; altitude permitted only with coordinates. Resolved timezone must be IANA and contain point; unconfirmed point cannot generate combined advice/notices. Cap 100 active distinct subscription locations transactionally; existing locations are shareable without extra quota.
- Launch exact requires net; window requires ordered bounds; date requires date_label and date_basis_timezone, with net null. Unknown has no exact countdown. net_precision mapping stores original external code in raw provenance. Actual liftoff requires confirming source, never wall clock. Unknown status disallows positive advice.
- Route association exact + approved, applicable validity, same pad/attempt and approved parser needed to admit. Hazard path_vertices must be empty; observations cannot admit reconstruction. Official region membership uncertain/outside does not prove invisibility. Polygon rings >=4 points closed and non-self-intersecting; GeoJSON interchange order longitude,latitude, while internal named fields prevent reversal.
- Profile samples strictly increase per stage; all required arrays equal length externally. WGS84 ellipsoid altitude required for calculation; MSL requires documented geoid conversion/version, unknown datum research-only. Source t is seconds from actual liftoff; downstream reuse aligns to hypothesized T0. Return-booster data excluded; source backed powered ranges nonempty for an admitted track. Training/holdout mission sets disjoint.
- Assessment input hashes bind launch, route, profile, location, weather, timezone, ephemeris, software/parser and rules. Route screening/unavailable windows empty. Official output only source-supported timing/direction: numerical reconstructed window fields must not be fabricated; official timing is in route.guidance and UI uses it directly. A later contract minor version may add a typed official display window, not reuse fake bearings.
- Reconstructed windows contain min<=max elevation; candidate IDs are retained. Bare hazard/observed sighting cannot produce Worth a look. Terminal/disabled status has no actionable windows and Not enough data as advice, with separate display_status. Geometric negative may have empty windows and Unlikely only if complete/fresh required inputs.
- NWS percent bounded 0..100. Unknown source units reject; zero visibility valid. Fetch time is separate from issue time and valid interval. Absence explicitly listed; missing layers use total_only. Conflicting overlapping fresh bins use worse tier.
- Subscription owner and secrets are not exposed in public DTO. Client cannot set revision/delivery state. Email omitted from baseline endpoints; optional adapter adds a separate verified-address contract and release gate. Valid unsubscribe capability disables and cancels atomically; DELETE is idempotent.
- Notification key is (subscription_id,attempt_id,notice_type,material_revision), persisted as a unique database constraint; material revisions persist across worker restart. Recipient delivery rechecks enabled consent and current assessment/status under row lock. Token/email never appear in notification DTO or logs.

API details: array list endpoints use opaque cursor and limit<=100; next cursor in `X-Next-Cursor`, absent when exhausted; stable sort (net null last,id) or (created_at,id). ETag is object revision; PUT subscription requires `If-Match`, missing =>422, stale =>409. Create subscription requires `Idempotency-Key`; replay same body returns existing record, different body=>409; keys scoped to session, retained 24h. API error DTO has stable code, request ID and no provider secrets. Input failures 422, missing resource 404, ownership violations 404, expired session 401, CSRF/admin access 403, rate limit429 with Retry-After, systemic outage503; a valid assessment with missing upstream evidence is 200 Not enough data, never fake success. Long computation can return503 retryable until cached; synchronous target <2s cached.

GET endpoints have no mutations except observability counters. Local session POST performs origin checks and issues server-generated >=256-bit capability; POST mutations require CSRF except unsubscribe bearer capability and admin bearer. Token delivered in recovery UI once; only salted hash stored. Browsing-only chosen coordinates may remain local; server transient resolved points expire after24h unless subscribed. Session ownership required for calendar assessment. ICS RFC5545 UTF-8 CRLF, escaping and folding at75 octets; UID attempt/location stable pseudonymous hash, SEQUENCE material revision, DTSTAMP UTC, DTSTART/DTEND supported view bounds; date-only unavailable for precise event. No automatic calendar alarms without explicit selection, no live-feed promise.

Repository contract checks validate schemas, examples, provider samples, OpenAPI and traceability. Cross-field behavior belongs to acceptance adapter and must not be silently waived because JSON Schema validates.

Candidate-track.schema.json binds each reconstructed correlated path to route/profile hashes. `t_s` is hypothesized-liftoff relative; after confirmed liftoff bind a new assessment with actual T0. Segment IDs prohibit bridging missing samples/stage changes. Guidance membership always includes location_id; a region inclusion result for one point cannot be reused for another location.
